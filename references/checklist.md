# 检查清单

## 开工前

- [ ] 目标一句话能说清（含验收标准）
- [ ] 用 3 个关键词搜过现有实现
- [ ] 定了预算：净增行数 / 新文件 / 新依赖
- [ ] 能回答「第二个调用者是谁」
- [ ] 真正需要问用户的问题不超过 1 个（能查就别问）

## 写的时候

- [ ] 只碰任务相关文件，不顺手重排
- [ ] 复用现有函数、类型、错误、日志
- [ ] 不新增依赖（除非省 30+ 行且维护活跃）
- [ ] 不新增配置项（除非部署环境确实不同）
- [ ] 不写「将来可能」的参数 / 钩子 / 插件点
- [ ] 内部不重复校验
- [ ] catch 要么处理、要么补语义；不吞异常、不只 log 再 throw
- [ ] 注释只写 why，不复述代码
- [ ] 命名短而准，不用缩写堆
- [ ] 不留调试输出（console.log / print / debugger）
- [ ] 单函数 ≤ 60 行、参数 ≤ 4、嵌套 ≤ 4
- [ ] 同段逻辑第二次出现可以接受；第三次再抽象

## 交付前

- [ ] 跑 `bloat.mjs --diff`（路径见 SKILL.md）
- [ ] 过一遍 SKILL.md 里的 5 个问题
- [ ] 按删减优先级扫一遍：
  1. 没被调用的代码 / 文件 / 导出 / 依赖
  2. 只有 1 处用的间接层
  3. 重复的校验 / 日志 / 错误包装
  4. 未使用的配置 / 参数 / 开关
  5. 为「以后」准备的接口 / 钩子
  6. 复制粘贴的块
  7. 注释掉的代码 / 过时 TODO
- [ ] 超预算的地方有说明
- [ ] 回复里写了删了什么

## 阈值速查

- 净增行数：≤ 150（小改动 ≤ 50）
- 新文件：≤ 3
- 新依赖：0
- 单函数：≤ 60 行
- 认知复杂度：≤ 15
- 圈复杂度：≤ 10
- 参数：≤ 4
- 嵌套：≤ 4
- 重复 5 行块（diff 内）：0
- 未使用导出 / 依赖：0

## 审查别人的代码时

按影响排序，不按风格：

1. 正确性与边界（最先）
2. 有没有更小的改法
3. 抽象 / 分层是否必要
4. 重复与死代码
5. 命名与注释
6. 风格（最后，别展开）

输出最多 5 条，标「严重 / 建议」，每条给最小改法，不重写整段。

## 交付说明模板

「改了 X（+N / -M 行，K 个文件）；删了 Y；新增依赖：无；检查：通过 / 未通过及原因。」
